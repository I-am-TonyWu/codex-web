# Antigravity 本机任务接入远程网页：初步评估

评估日期：2026-10-11。范围为只读调查；未开启远程权限、修改登录、发送模型任务或加入提供方切换。

结论：可行。若希望统一使用本项目网页，需要独立的 Antigravity 后台适配层，不能用 OpenRouter 或自定义模型 API 的切换代替。先保持 Codex 单后台运行，验证 Antigravity 的生命周期、事件和审批后再考虑统一入口。

## 已有能力与本机证据

Google 官方文档已提供 Antigravity 2.0 与 CLI 的 Remote Control：桌面启用后，可在官方网页使用同一 Google 账户访问主机实例；CLI 也支持交互连接及后台守护进程。它已经满足“本机运行、远端浏览器使用”的大部分需求，但入口由 Google 提供，并非本项目自建域名。账户是否具备该功能、本机设置是否开启，尚未验证。[官方 Remote Control 文档](https://www.antigravity.google/docs/remote-control)

本机安装的 Antigravity EXE 文件版本为 2.22.0。已有独立 Antigravity Web 程序，其本机健康接口返回运行正常并要求网页登录。已只读核对桥接代码及已安装程序的 `agentapi --help`：现有桥接通过 language_server 的 agentapi 创建会话、发送消息，读取 SQLite 会话摘要与本地记录，并依赖桌面语言服务地址与 CSRF 信息。此调查证明桥接路径存在，尚未验证一次完整模型任务。

官方 CLI 另提供结构化与流式输出以及继续会话能力，适合评估自建后台的程序接口；CLI 与当前桌面会话的身份及历史映射仍需实测，不能把“CLI 能继续自身会话”等同于“能无缝接管任意桌面会话”。[官方 Headless 文档](https://www.antigravity.google/docs/cli/headless/)

## 接入选择

| 方案 | 能完成什么 | 判断 |
| --- | --- | --- |
| 官方 Remote Control | 通过官方浏览器入口连接本机桌面或 CLI | 首先验证；维护成本低，但不复用本项目网页或域名 |
| 复用已有本机 Web 桥接 | 保留本机桌面任务、摘要、项目和文件访问 | 原型可行；内部 agentapi、日志和数据库格式需版本兼容检查 |
| 官方 CLI 驱动独立后台 | 创建任务并处理结构化事件 | 适合后续适配验证；桌面旧会话、停止和审批需另行证明 |

## 进入实现前的验收

1. 同一工作区分别完成创建会话、接续、流式进展与完成状态；核对网页与桌面任务 ID。
2. 验证等待审批、回答问题、停止任务、断线重连及重启后的状态恢复。已安装 agentapi 帮助未列出停止和审批命令，不能先宣称支持。
3. 文件、图片和产物按本机工作区授权访问；浏览器不接触 CSRF、账户凭据或内部语言服务端口。
4. 多窗口时准确选择主机工作区，建立与 Codex 相同的单写入方规则，避免重复发送；不得通过数据库改写伪造会话状态。
5. 健康检查按各后台能力独立实现，避免用 Codex 账户检查判断 Antigravity 是否健康。适配失败时保留草稿和历史。

本轮不改动现有 Antigravity Web 程序，不新增切换接口。后续建议先做隔离的 Antigravity 验收，再决定是否整合两个后台。
