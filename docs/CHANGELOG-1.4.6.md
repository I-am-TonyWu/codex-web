# 1.4.6 本地修订

2026-10-11。本地构建、安装和验证，本轮不发布 GitHub。

网页接续桌面对话后打开桌面出现“ChatGPT 遇到了问题”：网页发送文本缺少 `text_elements` 数组，桌面客户端 26.1007.2314.0 的连续对话检测器直接对它调用 `.some()`，触发界面错误边界。现在前端和队列文本补齐空数组，服务入口及桌面协同入口也规范化旧浏览器输入；已有文本元素、图片和技能引用保留，历史文件不改写。

按用户要求，网页新对话与桌面协同发送共用服务权限配置，默认 `danger-full-access` + `never`：网页发出的新轮次可以访问本机文件和网络，不逐项询问命令或文件权限。每轮显式应用该默认，避免恢复旧对话时继承旧限制。通过环境变量明确配置的受限模式仍生效；网页不能通过请求参数覆盖服务策略。桌面自行发送的轮次使用桌面设置。

权限请求、工具登录或需要用户选择的询问有各自的协议；本次没有批量替用户回答历史待处理请求。对话控制权、请求去重、忙碌检查、停止确认及账户凭据边界继续使用原实现。

验证：94 项相关单元测试；3 轮真实隔离 Codex writer + 本机模拟提供方 + 桌面 IPC 协议夹具；使用本机安装桌面检测器重现缺字段错误并验证规范化后不再触发。没有调用真实模型、发送实际用户草稿、重写历史或修改桌面安装文件。
