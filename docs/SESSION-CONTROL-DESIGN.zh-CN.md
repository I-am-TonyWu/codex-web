# 同一用户多端会话控制与交接设计

日期：2026-10-09。本文是设计方案，不代表功能已上线；当前安装版本仍为 1.4.3.6。

## 结论

目标是：同一对话允许多个终端查看，但同一时刻只有一个终端有权发送、停止、引导任务及处理审批。最新一次**成功确认的接管操作**取得控制权。打开页面、刷新、后台心跳和延迟到达的旧请求都不构成接管。

网页之间可以由现有网页服务统一协调。桌面端交接还需要可靠的桌面控制适配器；当前托盘没有控制桌面原生会话的通道，不能承诺仅加一个按钮就能通用释放桌面占用。上次在 Codex 当前会话内调用原生归档/恢复成功，不等于该能力已提供给托盘。

## 当前已经确认的实现

- 网页 A、B 共用 `getSharedBridgeState()` 创建的同一个 `AppServerProcess`，不会各自产生独立 Codex 写入锁。
- 1.4.3.6 已按 thread ID 串行协调网页进程的写入生命周期，历史查看不恢复写入，任务结束释放自己的闲置会话；它尚无按浏览器区分的控制权或过期请求拒绝机制。
- `codexui/thread/release` 只释放网页自己的非执行会话。向网页 app-server 发送 `thread/unsubscribe`，无法取消桌面 app-server 的订阅。
- 托盘管道当前只提供服务启停、重启、设置和 Access 检查等功能，没有针对桌面原生 thread ID 的释放命令。
- 桌面显示的页面、最后一条历史是否完成，都不足以单独证明后台没有任务。网页进程的 `notLoaded` 只表示它自己没有加载，不能证明其他进程闲置。

接口依据：[OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#unsubscribe-from-a-loaded-thread)：取消订阅针对当前连接；确认取消订阅后，会话关闭还需等待。停止正在执行的轮次是另一个操作，需要等待任务最终状态。本文使用实际安装 CLI 的行为核对兼容性，不依赖文档默认卸载时间与本机相同。

## 两层管理

| 层次 | 管理对象 | 解决的问题 |
|---|---|---|
| 原生写入权 | 哪个 Codex 后台进程能写入此 thread ID | 桌面进程与网页进程冲突 |
| 终端控制权 | 哪个已认证浏览器实例可以控制任务 | 网页 A、B 共用进程时的冲突、旧页面误操作 |

会话状态至少保存 thread ID、控制终端、控制版本、活动 turn ID、待处理审批/队列、交接状态、上次有效心跳。浏览器实例按标签页区分，不按邮箱区分；同一个邮箱可登录多台设备。控制凭证由服务端签发并绑定认证会话、终端、thread ID 与版本。

控制权和原生写入权分开：没有执行任务时，网页可释放实际写入锁；界面上保留短期终端控制状态，发送前再取得实际写入权。

## 完整状态与操作

| 状态 | 网页显示 | 新终端的明确操作 | 处理结果 |
|---|---|---|---|
| 没有控制者、没有任务 | 可开始对话 | 发送或接管 | 服务端原子分配控制权；发送时恢复原会话 |
| 当前终端控制、闲置 | 本终端可操作 | 发送 | 核对控制版本和原生写入权后创建一次新任务 |
| 其他网页控制、闲置 | 由网页 A 控制 | 接管此对话 | 控制版本递增，A 降为观察；B 保留原 ID、历史，可手动发送 |
| 其他网页控制、正在执行 | 网页 A 的任务正在执行 | 接管控制，任务继续 | 只转移终端控制权；同一后台任务继续，B 可处理审批、引导或停止，A 观察进度 |
| 网页任务执行中，想立刻开始新的轮次 | 当前任务尚未结束 | 停止当前任务并接管 | 请求中断，等待任务结束与保存，然后交接；不自动发送草稿 |
| 桌面后台持有、确认闲置 | 桌面客户端保留此会话 | 释放桌面会话并接管 | 必须由已验证桌面适配器执行原生释放，再确认网页恢复成功 |
| 桌面后台持有、正在执行 | 桌面任务执行中 | 完成后接管，或停止并接管 | 由桌面适配器等待/请求中断；结束并保存后释放，网页恢复原 ID |
| 桌面后台持有、状态未知或适配器不可用 | 无法确认桌面执行状态 | 重试连接 | 保持只读并说明缺少控制通道；不能假装已释放 |
| 正在交接 | 正在交接，请稍候 | 查看、取消尚未提交的接管意图 | 暂停新的会话修改；完成后只有一个终端得到有效控制凭证 |
| 网络断开或原生状态不确定 | 正在重新连接/确认状态 | 重连 | 查询权威状态；任务继续，不重复发送、不把超时当作空闲 |

网页 A/B 共用一个执行进程时，接管控制通常无需中断模型，也无需先卸载再加载。桌面与网页是两个执行进程，不能假设正在运行的任务能无缝换到另一个进程；需要原进程协作，或未来统一执行后台。

## 接管流程

1. 客户端读取服务端状态；占用提示显示终端来源、是否执行及可用操作。只有成功读取后才描述为闲置，未知明确显示未知。
2. 用户明确点击接管。请求携带唯一请求 ID 与所见控制版本。仅选中/浏览对话、打字草稿，不抢控制。
3. 服务端按 thread ID 原子协调；旧版本请求被拒绝并返回新状态。避免页面恢复、旧心跳、延迟的停止/审批请求重新取得权限。多个同时接管请求不能同时成功；新操作以服务端确认结果为准，不比较设备时钟。
4. 网页之间直接更新控制版本，广播 A 的观察身份和 B 的控制身份。当前任务继续；若用户选择停止，则等待明确中断结束。
5. 桌面交接必须走桌面原生控制通道，确认没有未结束的关联任务/审批。只有实际关闭确认及原 ID 恢复成功后，才能宣布接管完成。
6. B 成功后刷新最新历史、任务和审批状态。A 的草稿仍保存于 A，B 的草稿仍保存于 B；两者不覆盖或自动发送。
7. 每次发送、引导、停止、审批及会话修改，由服务端重新校验控制凭证。旧页面即使界面按钮未及时变灰，也没有修改权限。
8. 交接失败或超时返回可读原因和当前已知状态。若停止或释放已发生，记录实际进度，不能回报旧任务仍正常运行；若原 ID 恢复尚未成功，保留只读重试，不自动分支或重发。

## 退出、断线与自动释放

- “退出此对话的控制”只退出控制，不删除、归档或隐藏历史，也不退出整个 Codex 或托盘。
- 离开对话、退出网页登录时：没有任务就释放终端控制；已有任务继续执行，其他终端可接管控制。
- 初始建议心跳 5 秒，30 秒未收到有效心跳视为终端失联。失联只影响控制权，不取消模型/文件任务、不代表原生锁已释放。重连取回身份需要核对最新控制版本，不能自动抢回。
- 手机后台、休眠、断网无法保证发出退出通知，因此必须依靠服务端心跳与任务状态，不能只靠网页关闭事件。
- 任务完成后释放网页原生闲置写入权；重新发送前再恢复。后台队列不能绕过交接继续替旧终端发起下一条消息；草稿/未执行队列需按来源保留并明确标记。
- Windows、服务重启后，原控制凭证全部失效；原生锁必须重新检查。已接受消息按持久化请求 ID 查询结果，无法确认是否创建轮次时不自动重发。

## 需要防止的边界问题

1. **任务部分完成**：停止任务不撤销已经执行的文件修改或外部操作；不能称为“无损暂停”。保留已完成步骤和中断标记，后续继续是新轮次。
2. **等待审批/后台命令/子任务**：这些不等于闲置。审批只能由当前控制终端回答；旧终端的迟到回答作废。无法确认关联活动时不自动进行桌面恢复。
3. **消息重复**：每条发送分配请求 ID，持久记录已接受状态与 turn ID。HTTP 超时、重连和再次点击不能重复创建模型任务；不确定时查历史与任务状态。
4. **会话与文件冲突不同**：不同对话可以独立运行，但若修改同一项目目录，仍可能冲突。创建分支也不会自动隔离共享项目文件。
5. **归档/恢复的副作用**：官方归档可能涉及子对话，因此不能把上次修复方法普遍包装成无副作用的“释放”。若保留为受控恢复方案，需核对关联会话、归档状态与项目归属；失败可恢复，不适用于未知活动状态。
6. **不能跳过真实锁**：删除锁文件、结束整个桌面 app-server、重启托盘或网页服务，不属于正常会话交接；可能影响其他任务，也不能保证消除桌面占用。
7. **权限来源**：控制端点继承已认证站点权限，服务端检查会话与控制版本；仅接受指定 thread ID 的有限操作，不能开放任意 PID 结束或任意系统命令入口。

## 桌面适配器的能力边界

当前独立桌面进程没有向托盘提供已验证的通用释放接口。仅使用网页 app-server 的 RPC 不足以远程控制它。

适配器上线前必须验证：定位真实原生会话、可靠读取当前执行状态、请求停止、关闭并保存指定会话、确认写入权释放、恢复原 ID、失败恢复以及不影响其他对话。缺任意关键能力时显示“桌面远程释放暂不可用”。上次 Codex 工具的成功操作不能作为可打包 API 的证明。

真正实现 Windows/所有网页完全对称的“最新操作优先”，需要桌面也遵守同一个控制协调器或共享执行后台。当前桌面客户端不由本项目维护，尚未验证这种接入方式。只加网页终端控制权能完整覆盖网页 A/B；桌面端必须作为独立后续验证阶段，不能承诺直接接管所有后台任务。

## 实施阶段与验收

第一阶段：网页终端控制权、接管/退出按钮、控制版本、断线恢复、旧请求拒绝及消息去重。复用现有 app-server；正在执行的网页任务接管后继续。

第二阶段：验证桌面适配器。通过指定会话正常关闭/恢复的真实测试后，才启用桌面释放按钮；若不可行，保留明确限制，不用结束整个进程代替。

第三阶段：如有受支持且验证可用的统一桌面/网页执行后台，再实现双向自动交接；需另行验证桌面启动、版本升级、审批及插件兼容。

验收覆盖：A→B 闲置接管；A→B 执行中继续；明确停止后接管；待审批交接；双端同时抢占；旧心跳/发送/停止/审批迟到；手机后台和断网；服务重启；桌面闲置/执行/未知三状态；桌面归档涉及子会话；原 ID/历史/项目归属/双端草稿不变；同一请求只创建一次模型轮次；不同对话任务不被误停。
