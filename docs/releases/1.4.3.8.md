# 1.4.3.8 — 历史对话写入恢复 / Historical thread writer recovery

修复 1.4.3.7 中历史对话发送失败后，“被占用”旧状态持续禁止发送的问题。稳定版仍为 [1.4.3.6](https://github.com/I-am-TonyWu/codex-web/releases/tag/v1.4.3.6)，[1.4.3.7](https://github.com/I-am-TonyWu/codex-web/releases/tag/v1.4.3.7) 及[全部历史版本](../RELEASES.md)继续保留。

## 相较于 1.4.3.7

- 明确区分网页标签页控制权与本机 Codex 进程写入锁。初始提示改为“尚未取得网页控制权 · 发送时检查本机写入状态”，不再暗示本机没有占用。
- 外部占用提示代表上一次实际检查；不再永久禁用当前控制网页的发送按钮。用户手动再次发送时，仍由原生 Codex 验证写入锁，成功前不会创建模型轮次。其他网页观察者及交接中仍禁止发送。
- 控制栏增加“重新检查写入状态”：重新验证原对话的真实写入权，成功后立即清除错误并恢复发送。检查不发送草稿、不创建分支、不取消任务；只释放本网页后台新取得的闲置 writer。正在运行的任务保持运行。
- 原有“重试原对话”使用同一检查逻辑，只返回短状态数据，不重复传输整段历史。新检查通过服务端控制凭证校验，旧网页不能借此重新取得原生写入权。
- RPC 成功或拒绝直接携带当前控制状态；状态修订号防止迟到的轮询响应把已恢复的状态改回“被占用”。心跳和普通刷新只查询元数据，不每五秒 resume 历史。
- 已确认开始的网页任务在原生元数据缓存更新前，也会阻止后台队列启动下一轮。
- 密码、Cloudflare Token、邮箱、项目和历史保存方式保持兼容。

## 使用与边界

升级后刷新所有网页。打开历史并输入要求，可以手动发送；如提示上次占用，可点顶部“重新检查写入状态”或下方“重试原对话”。检查成功后原稿保留，由用户再点发送。

桌面关闭聊天页面不保证后台释放写入锁。如果锁确实仍由桌面或其他 Codex 进程持有，检查仍会准确报告占用。**本版不包含通用桌面远程释放适配器**，不会强制结束桌面进程、删除锁或自动归档用户对话。网页控制权不能覆盖原生 OS 写入锁。原生客户端正常释放后无需新建分支，即可继续原 ID。

同邮箱或不同邮箱依然共享同一 Codex 环境。不同版本切换及回退前的队列处理见[版本切换说明](../RELEASES.md)。

## 验证

102 项相关单元回归与 7 项 writer 桥接恢复测试通过；真实隔离 Codex app-server + localhost 模拟提供方验证外部写入锁、释放后原 ID 重查、闲置检查释放、发送去重、过期控制凭证拒绝及队列暂停。八组原对话恢复 UI 覆盖 375×812、768×1024 明暗主题及“先检查”和“直接手动发送”两条路径，另有四组两标签页交接回归。无真实模型调用。生产构建、CLI 入口与托盘配置测试单独核对。

性能：常规状态轮询仍是内存元数据读取；只有明确点击检查才调用一次原生 resume，HTTP 检查响应为短控制元数据（隔离测试小于 1.5 KB），不带历史正文。普通 RPC 返回增加一个短状态快照，避免额外状态请求。没有引入锁扫描、全历史轮询或后台模型请求。

Docker 不可用，Docker 矩阵未执行。手机实机与 Windows 重启后验收仍需现场核对。本机目标对话的手工原生释放属于此次维护操作，并不是安装包中的自动桌面释放功能。

## English

Fixes a sticky external-writer state that disabled sends after a historical conversation was blocked in 1.4.3.7. Browser control and the native OS writer lock are now described separately. A previous conflict no longer permanently disables a controller's manual send; native resume still validates exclusive write access before a turn is created.

The control bar adds **重新检查写入状态 / Recheck writer access**. Both this action and the existing retry action return compact control metadata, preserve the original ID and draft, and never send, fork or interrupt automatically. The probe releases only its own idle writer. Running tasks stay active. Stale controllers are rejected before the probe.

RPC responses carry the latest control snapshot. Revisions prevent late polling responses from restoring a stale conflict. Ordinary five-second polling does not resume threads. Confirmed active web tasks also block queue draining before native metadata caches catch up.

**A portable remote desktop-release adapter is still unavailable.** Closing a desktop view can leave a native writer subscribed. A real external lock remains authoritative until normally released; this release never kills the desktop process, removes its lock or automatically archives user threads. The stable 1.4.3.6 release and all published previews remain downloadable.

Reload browsers after installation. Local credentials and data remain compatible. See the Chinese validation section for test coverage, performance and unverified physical-device/reboot coverage.
