# 1.4.3.9 — 桌面后台协同 / Desktop thread coordination

1.4.3.8 能清除旧的占用状态，但桌面 Codex 实际持有会话时，网页自己的 app-server 仍无法取得写入锁。桌面离开页面后，其后台可能继续保留会话数小时。本版为这一情况增加同一 Windows 用户的本机 IPC 协同通道。

## 相较于 1.4.3.8

- 发送前如果原生 resume 返回 active-writer 冲突，尝试发现真正持有该 ID 的桌面后台，并检查模型设置和版本匹配的会话快照。成功时显示“桌面后台协同”，仍在原 ID 中继续，不另建分支。
- 用户手动发送后，请求交给持有会话的后台执行，避免第二个 app-server 争抢写入锁。网页标签页之间的控制凭证、发送编号去重和旧请求拒绝继续有效。
- 接收桌面的会话快照与增量，同步消息、命令、完成状态和待审批请求；网页的审批和明确停止通过同一持有者返回。
- 协同发送明确使用 workspace-write 沙箱和 on-request 审批，避免继承桌面会话可能使用的完全访问权限。附件、技能/插件输入、模型和推理强度随手动消息传递。
- 桌面忙碌、待审批、发送结果不明，以及快照中可见的排队消息或活动目标会阻止第二次发送。断线、版本不匹配、增量序号缺失或接受结果缺少 turn ID 时不自动重发。
- 退出网页控制只取消网页协同订阅；闲置订阅一分钟没有使用时也自动撤销，后续手动发送可以重新连接。不强制停止 Codex，不删除锁文件，不自动归档对话。
- 升级保留密码、Cloudflare Token、邮箱、项目和会话数据。

## 使用

升级后刷新网页，打开原对话。可点“重新检查写入状态”，看到“本网页控制 · 桌面后台协同”后再手动发送；也可直接手动发送，由后台检查并连接。检查与接管均不会自动发送草稿。

Windows Codex 必须正在运行且使用同一 Windows 用户。协同通道是客户端内部接口，已核对本机 Windows 客户端 26.1002.7124.0 / Codex CLI 0.162.0-alpha.2；不是官方保证稳定的远程 API。将来客户端升级改变协议时，本版会拒绝不匹配的状态，并保留原有只读/重试/显式分支路径。不要把“协同”理解为已经释放桌面写入锁。

协同模式目前支持发送、停止和审批。归档、回滚等操作暂不能通过该通道执行；需要在客户端操作或正常释放后操作。客户端直接发起的操作仍由原生后台协调；桌面单独的排队管理通道尚未接入，不能保证覆盖与桌面同时排队的所有竞态。本版不宣称实现了所有桌面动作的网页抢占。

## 验证及实际边界

128 项相关单元测试、7 项桥接回归通过。隔离数据目录下，用真实 Codex app-server 持有原写入锁、桌面 IPC 协议测试服务与 localhost 模拟提供方验证：原 ID 接续、一次请求一次真实 turn、工作区沙箱参数、旧控制网页拒绝、完成和历史读取。IPC 测试服务代替桌面请求处理器；不得把这一项说成真实桌面模型回复已验收。

本机真实桌面通道读取目标历史 ID、真实 idle 状态与模型设置成功；移除 executor 的 app-tools pipe/任务环境变量后也能独立连接。没有发送用户的业务草稿或调用真实模型。前端覆盖 12 个 375×812 / 768×1024 明暗主题场景，含直接发送、原对话重试和桌面协同状态；草稿不自动发送。51 项托盘与安全配置测试通过。手机实机、真实桌面发送/回复及 Windows 重启需要用户现场验收。所有历史发行版保留，Latest 稳定版仍是 1.4.3.6。

## English

1.4.3.8 repaired stale conflict state, but could not acquire a writer still held by the desktop. This preview discovers the actual local desktop owner and uses its same-user coordination channel to continue the original conversation. It does not delete locks, terminate Codex, archive conversations or automatically fork.

Manual sends, explicit stops, streamed state and supported approvals use the identified owner. Browser control fencing and request deduplication still apply. Sends explicitly preserve workspace-write and on-request permissions rather than inheriting a desktop full-access setting. Running tasks, approvals, uncertain submissions and queued work/active goals visible in the desktop snapshot block a second send. Disconnects, incompatible stream versions and revision gaps preserve drafts and never trigger automatic retries.

Reload the web page after upgrading. Recheck access or send manually; **桌面后台协同 / Desktop coordination** indicates a successful connection. The desktop must run under the same Windows user. This relies on a version-checked internal desktop protocol, not a supported public remote API. Archive/rollback, the desktop separate queue-management channel, and complete desktop preemption remain unsupported.

Tests: 128 related unit tests, 7 bridge regressions, and a real isolated app-server with an IPC protocol fixture and localhost-only provider. The actual installed desktop was checked read-only without executor metadata. No real model requests or user business drafts were sent. Physical mobile, actual desktop send/reply and Windows reboot acceptance remain unverified. Stable Latest stays at 1.4.3.6, with previous previews retained.

## Performance / 性能

本机协同连接按需建立，检查/恢复不创建模型请求。更新合并为最多每 100ms 一批；最多保留 64 个订阅，空闲一分钟无读取时取消订阅；单帧上限 64MiB。每批只通知变化的 turn/item，初次快照不重放旧历史。生产 CLI 为 608.10KiB，前端构建通过；已有 Mermaid 大分块提示保留。尚未测量真实长历史持续生成时的 CPU/内存峰值，不能承诺长会话性能已验收。
