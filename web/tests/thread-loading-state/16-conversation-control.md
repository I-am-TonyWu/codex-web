# 1.4.3.7 会话控制验收

- 两个同源标签页 A/B 打开同一历史：无 thread/resume，无新轮次，B 不抢占。
- A 发送后 B 明确接管：原 ID/历史/项目不变，活动任务继续，A 变观察者。
- 旧发送、停止、审批、改名、回滚、归档、项目归属与终端写入请求必须服务端拒绝，不能仅依赖按钮禁用。
- A/B 同时用同一控制版本接管只有一个成功；浏览、刷新、草稿输入和心跳均不接管。
- 停止并接管：确认 → 原生 turn/completed → 新控制凭证。失败或超时不得宣布空闲，不自动发草稿。
- 两端不同草稿分别保留；发送成功清空的草稿不得从旧版共享存储复活。
- 手机后台/断网 30 秒后失联，任务继续。旧心跳不能恢复控制。离开对话不重新取得上一对话控制。
- 交接或重启后队列保留并暂停。同一请求只创建一个轮次；重启后仍可查发送记录。
- 桌面锁未知时说明适配器不可用并禁用桌面释放，不删除锁、结束进程或隐式分支。

自动验证：scripts/test-conversation-control-http.cjs（真实 CLI + 本地提供商，无真实模型请求）、scripts/test-conversation-control-ui.cjs（双标签页拦截）、scripts/test-writer-original-retry-app.cjs（恢复回归）。覆盖 375×812、768×1024、明暗主题，截图等待 2.3 秒。

性能：可见对话每 5 秒最多一次状态/心跳请求，隐藏页面暂停。心跳不读取完整历史；轮次通知复用现有监听；按 thread ID 串行。发送日志只有摘要和短结果；队列空闲检查 metadata-only。状态与凭证有上限，过期控制不会取消任务。

Docker 不可用，平台矩阵未执行。手机实机和 Windows 重启需另行复验。
