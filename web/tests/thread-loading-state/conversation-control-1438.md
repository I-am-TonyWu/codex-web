# 1.4.3.8 原对话占用恢复

前提：隔离 Codex 数据目录、两个真实 app-server 或模拟 API；不使用真实用户提示或模型权益。

1. 打开历史：不发 thread/resume，顶部区分网页控制权与本机写入状态。
2. 外部 app-server 持有闲置 writer，手动发送：提示上次检查占用、草稿保留、没有 turn/start。当前网页仍可明确再次发送；观察网页不能发送。
3. 锁仍存在时点“重新检查写入状态”：仍提示占用、不卸载外部 writer、不创建分支。检查响应不带完整历史。
4. 外部正常释放后，分别测试直接手动发送、先检查再发送：保持原 ID、历史、项目与草稿；每次明确发送只有一个新轮次，检查本身不发送。
5. 延迟返回旧 external 状态轮询：不能覆盖更新修订号的 idle 状态，按钮不再次被禁用。
6. 网页 B 明确接管后，网页 A 的旧凭证调用检查、发送、停止均拒绝，现有任务和两个草稿保留。
7. 375×812、768×1024 明暗主题截图检查所有顶部按钮完整可见，没有横向溢出。

清理：结束隔离服务与模拟提供方；不要删除真实锁文件。回退前保存并移除队列，再替换 EXE 并刷新网页。
